# 文档归档规则 (Documentation & Archival Rules)

---

## 1. 核心归档文件

| 文件 | 用途 | 更新频率 |
|------|------|----------|
| `task_plan.md` | 任务清单与进度 | 每个任务开始/完成时 |
| `progress.md` | 开发进度日志 | 每个 Task 完成后 |
| `findings.md` | 技术发现与决策 | 关键决策时 |
| `bugs.md` | Bug 记录与修复日志 | 每次 Bug 发现/修复时 |

---

## 2. 时间戳格式

所有文档更新**必须**带时间戳：

```
格式: YYYY-MM-DD HH:MM

示例:
  ## 2026-03-25 21:00 — Phase 1 Layer 1 Poller 完成
```

---

## 3. task_plan.md 状态标记

```markdown
- [ ] 未完成
- [/] 进行中
- [x] 已完成
- [!] 阻塞 (需人工介入)
```

---

## 4. bugs.md 记录格式

```markdown
## BUG-001: [标题]
- **发现时间**: 2026-03-25 21:00
- **严重程度**: Critical / Major / Minor
- **症状**: [具体错误现象]
- **根因**: [分析结果]
- **修复**: [修复方案]
- **修复时间**: 2026-03-25 21:15
- **回归测试**: PASS / FAIL
- **相关文件**: [文件列表]
- **自愈轮次**: 2 / 5
```

---

## 5. 会话归档检查清单

每次开发会话结束前**必须**执行：

```
归档检查清单:
  ☐ task_plan.md — 已标记完成项 [x]
  ☐ progress.md — 已追加本次会话摘要 + 时间戳
  ☐ findings.md — 已记录新技术发现（如有）
  ☐ bugs.md     — 已记录新 Bug 及修复（如有）
  ☐ Git commit  — 所有文档变更已提交
```

---

## 6. progress.md 格式

```markdown
## YYYY-MM-DD HH:MM — [会话标题]

### 完成事项
- [具体完成的任务]
- [具体完成的任务]

### 关键决策
- [做了什么决策，为什么]

### 下一步
- [下次会话的优先事项]

### 遗留问题
- [未解决的问题]
```

---

## 7. findings.md 格式

```markdown
## Finding vX.Y — [标题] (YYYY-MM-DD HH:MM)

### 背景
[为什么研究这个问题]

### 发现
[核心发现内容]

### 决策
[基于发现做出的决策]

### 影响
[对项目架构/开发的影响]
```
